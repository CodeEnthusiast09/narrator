## Design Specificity Verdict

**LLM assessment (Assessment A):** Mixed, leaning generic at the shell layer, genuinely specific at the functional core. The visual shell — near-black canvas, one indigo accent, flat tonal layers, bottom sheets, segmented pills, a circular FAB, gradient covers with a bottom progress bar — is the standard vocabulary of any dark-mode podcast/audiobook app template; strip the copy and it drops unchanged into a meditation app. What's genuinely load-bearing and couldn't be reused unchanged: the front-matter review sheet (per-page checkboxes, truncated preview text, two non-destructive bail-outs), sentence-level tap-to-seek, and the `CHAPTER_PAUSE`/`PARA_PAUSE` DOM spacers that visually mirror audio pacing with zero added chrome.

One specific tension worth naming: DESIGN.md's own north star promises "a small warm light held in a dark room," explicitly anti-clinical. The actual accent (`#818cf8`) is a cool periwinkle-indigo, not warm — the opposite of the amber/warm convention every night-reading tool (Kindle night mode, f.lux) converges on for exactly this use case (reduce blue light before sleep). The design system's own words promise warmth; the shipped hex delivers cool tech-SaaS blue. That's a real gap between stated intent and execution, not a nitpick.

**Deterministic scan (Assessment B):** `detect.mjs --json pwa` returned `[]` — zero findings, exit code 0. This was verified as a genuine true-negative, not a broken scan: a deliberately bad CSS snippet piped through the same detector correctly triggered `overused-font` and `bounce-easing` findings, confirming the engine works and simply found nothing to flag in this codebase. Worth noting explicitly: the detector's clean scan and Assessment A's 5 priority issues are not in conflict — the detector checks pattern-level anti-patterns (overused fonts, bad easing, hardcoded colors), not semantic correctness (ARIA state, copy accuracy, feature discoverability, persistence bugs), which is exactly the class of issue this review surfaced. Clean detector output describes the surface; it says nothing about whether the error copy points at a real button.

## Overall Impression

The technical execution is disciplined — token usage is consistent, typography is genuinely restrained, and the front-matter/resume flows show real product thinking. But this pass surfaced something the recent `/impeccable audit` → `/impeccable harden`/`adapt`/`optimize`/`colorize` cycle didn't and structurally couldn't: bugs and gaps that live in *correctness and completeness*, not *pattern compliance*. A promised persistence feature that silently doesn't persist. An error message pointing at a button that was never built. A blocking overlay with no way out. These are the kind of issues that erode trust in a tool used daily, precisely because they're invisible until the one moment someone actually needs them — and for a one-user personal tool, "someone" is always the same person hitting the same bug repeatedly.

## What's Working

1. **The front-matter review sheet** gives the user real agency over an automated judgment call — per-page checkboxes, preview text, two non-destructive bail-outs. It's the one screen unmistakably built for *this* product's actual differentiator (structure-aware narration), not borrowed from a template.
2. **Pause pacing made visible, not just audible** — `CHAPTER_PAUSE`/`PARA_PAUSE` render as sized blank blocks in the reading pane, so the visual rhythm quietly mirrors the actual audio pacing with zero added chrome. A specific, low-cost detail that reinforces the product's own positioning.
3. **Wake lock tied to the literal usage scenario** — `useWakeLock(status === 'reading')` paired with safe-area-inset handling everywhere shows real design-for-the-physical-situation (phone in pocket, walk away, come back), not a generic mobile checklist item.

## Priority Issues

**[P1] Playback speed silently doesn't persist, contradicting PRODUCT.md**
- **Why it matters**: `useTTS.ts` writes `pitch` to `localStorage` on every change but never does the same for `speed`, despite PRODUCT.md explicitly stating speed is "persisted." The app's one user has a daily preferred pace and has to re-select it after every single open — a promise the product record makes that the code silently breaks.
- **Fix**: Mirror the pitch pattern — read `narrator_speed` on init, write it in `setSpeed`.
- **Suggested command**: `/impeccable harden`

**[P1] Blocking overlays have no escape hatch**
- **Why it matters**: The front-matter/resume/done overlay backdrop (`Player.tsx:389`) has no dismiss handler, unlike the Settings sheet's backdrop (`:271`), which does. It fully covers the header, making the always-visible Close button unreachable. Opening the wrong PDF leaves no way back to the library short of completing the sheet's own forced decision tree.
- **Fix**: Add tap-outside-to-close on the backdrop, or an explicit "not now" affordance that routes back to `close()`.
- **Suggested command**: `/impeccable harden`

**[P1] Error copy tells the user to tap a button that doesn't exist**
- **Why it matters**: `usePlayer.ts:198,206` — both permission-error strings say "Tap the + button to open the file again." No "+"-labeled or "+"-shaped control exists anywhere in `BookPicker.tsx`; the actual control is a document-icon dropzone reading "Open a PDF." This fires exactly when a returning user hits a browser permission quirk after restart — already a known pain point this repo has fixed once before — and the recovery instruction is simply wrong.
- **Fix**: Reword to match the real UI ("Tap 'Open a PDF' to open it again"), or better, surface a direct retry action inline instead of a text instruction.
- **Suggested command**: `/impeccable clarify`

**[P2] Tap-to-seek, a documented feature, has zero discovery affordance**
- **Why it matters**: The only styling signal for seekability on sentence spans is `cursor-pointer`, which has no effect on Android/touch — the app's confirmed target platform. No icon, underline, or first-use hint exists. A capability PRODUCT.md lists as confirmed functionality is invisible to anyone not already told it exists.
- **Fix**: A one-time first-session hint, or a persistent subtle affordance (e.g. dotted underline) that survives past onboarding.
- **Suggested command**: `/impeccable onboard`

**[P2] Custom controls expose zero semantic state to assistive tech**
- **Why it matters**: Grep across `components/` confirms zero `aria-pressed`, `aria-checked`, or `role="radiogroup"` usage anywhere. Every segmented-pill group (speed, pitch, sleep timer, font size) and the front-matter checkboxes convey "selected" through color alone — a screen reader announces "button," never the state. No `focus:` styling is defined anywhere either (the browser's default outline isn't suppressed, so keyboard users aren't stranded, but there's no deliberate focus treatment matching the rest of the system).
- **Fix**: Add `aria-pressed`/`aria-checked` to every toggle-style control; consider `role="radiogroup"` for the pill groups.
- **Suggested command**: `/impeccable harden`

## Persona Red Flags

**Sam (accessibility-dependent, screen reader/keyboard-only)** — worst-fit persona for this app as shipped.
- Front-matter checkboxes are `div`-based custom checkmarks inside a button with no `aria-checked` — announced only as "button," never its state.
- All four pill groups (speed/pitch/sleep timer/font size) convey selection through color only, with zero ARIA state, confirmed by repo-wide grep.
- Tap-to-seek sentence spans are plain `<span onClick>` elements — not buttons, no `role="button"`, no label. A screen reader user gets no indication these are interactive at all.

**Casey (distracted, thumb-only, interruptions)** — directly named in PRODUCT.md's own "commute, chores, exercise" context.
- The tap-to-seek hit target is the rendered word glyph itself — no padding, no minimum touch-target sizing — a stark contrast to every other control in the app (Close/Settings/prev-next/remove), all correctly sized to ~44px from the recent `/impeccable adapt` pass. Precise sentence-seeking while walking with a thumb is the one interaction that doesn't meet the app's own standard.
- The book-cover open button has no `active:` pressed-state class (confirmed by grep — zero `active:` usages in `BookShelf.tsx`), unlike nearly every other interactive element in the app. On a distracted thumb-tap there's no tactile confirmation before the library screen navigates away.

**Riley (deliberate stress tester)**
- The permission-denied-after-restart flow is precisely the "refresh mid-flow" scenario this repo has already fought once (per its own commit history) — and the error copy that fires in that exact path points to the nonexistent "+" button.
- Opening the wrong PDF and wanting to bail during front-matter review hits the overlay-trap issue above — there's no tested path back to the library short of finishing the flow.

## Minor Observations

- DESIGN.md states the segmented-pill pattern is used for "every 'pick one of N' decision... never a dropdown, never a radio list," but the Voice selector is a vertical list of full-width buttons — functionally a radio list, contradicting the design system's own stated invariant for exactly the control it names.
- `--color-accent-dim` (`#3730a3`) is declared in the theme and the DESIGN.md sidecar but never referenced by any component — a confirmed dead token (DESIGN.md already documents this honestly as "reserved, not proven").
- Four separate settings decision points (speed: 6 options, pitch: 5, sleep timer: 6, voice: uncapped) each exceed the ≤4-choice cognitive-load guideline; font size additionally offers two redundant controls (A-/A+ stepper *and* a 5-way pill row) for one decision with no stated rationale.
- The "Finished" overlay reuses the same checkmark-in-circle glyph already used for a front-matter checkbox tick, and shows nothing beyond title + Close — the least distinctive screen in the app, for what PRODUCT.md defines as the app's actual success moment.
- `lib/pdf.ts`'s `extractPages` doesn't wrap pdfjs-dist parse failures in a friendlier message before they reach the user-facing error text.
